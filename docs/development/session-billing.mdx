# Session Billing — Anthropic-Style Rolling 5-Hour + Weekly Window

Implement a per-user token metering system modelled on Anthropic's Claude session limits:
a **rolling 5-hour token budget** and a **fixed calendar-week budget**, both with
**peak/off-peak weighting**, automatic pause when the budget is exhausted, and unblocking
as old activity rolls out of the window.

---

## Why

LobeHub already measures every token that flows through the agent runtime.
The `ModelUsage` shape (input/output breakdowns, cache-hit/miss, cost) is
persisted in `messages.metadata.usage` per assistant turn. What's missing
is a metering layer that aggregates over time and gates new requests per user.

`messages.metadata.usage.cost` captures what LobeHub **pays** the provider.
`usage_events.cost_cents` captures what LobeHub **charges** the user — a
separate billing layer with a configurable markup.

---

## Architecture

```
User request
  │
  ▼
sessionLimitGuard middleware         ← assertBudget(userId) — blocks if over limit
  │                                     applied at aiChatProcedure level (aiChat.ts)
  ▼
createRuntimeExecutors (call_llm)    ← existing server-side agent executor
  │
  ├─ AccumulateLLM (already exists)
  │
  └─ recordUsage(userId, messageId, modelUsage)   ← NEW: awaited inline, appends to usage_events
```

### Token basis

```
raw_tokens = modelUsage.totalTokens   // totalInputTokens + totalOutputTokens
                                      // cache hits count at full weight
```

### Rolling window calculation (5-hour session)

```sql
SELECT SUM(weighted_tokens), MIN(occurred_at)
FROM usage_events
WHERE user_id = ? AND occurred_at > now() - INTERVAL '5 hours'
```

`resetsAt = MIN(occurred_at) + 5 hours`. Returns `null` when no events exist.
Shown in the UI only when `used / limit >= 0.8`.

### Fixed calendar-week calculation

```sql
SELECT SUM(weighted_tokens)
FROM usage_events
WHERE user_id = ? AND occurred_at >= date_trunc('week', now()) + INTERVAL '0 days'
```

Resets every **Sunday 00:00 UTC**.

### Peak / off-peak weighting

```
weighted_tokens = raw_tokens * peakMultiplier(occurred_at)
```

Peak hours: **5:00–11:00 AM PT** (single canonical window; the GMT description
in the original spec was a duplicate). Binary multiplier — no gradient.

| Period   | Multiplier                                      |
| -------- | ----------------------------------------------- |
| Peak     | `SESSION_BILLING_PEAK_MULTIPLIER` (default `2`) |
| Off-peak | `1`                                             |

DST is handled by evaluating `occurred_at` in America/Los\_Angeles time.
Unit tests must cover the PT spring-forward (`2024-03-10`) and fall-back
(`2024-11-03`) boundaries explicitly.

### Block threshold

`assertBudget` throws when `used > limit` (strict greater-than).
A turn that lands exactly at `used === limit` is allowed through;
the *next* request is blocked. This matches the one-turn-lag behaviour
described below.

### One-turn lag (v1 accepted behaviour)

The guard reads budget from *completed previous turns* — the current turn's
tokens aren't known until the stream finishes. `recordUsage` is **awaited
inline** before the stream response returns, so the next client request
always sees an up-to-date budget. Pre-flight estimation is deferred to v2.

### User-facing charge

```
costCents = Math.round(modelUsage.cost * SESSION_BILLING_COST_MARKUP * 100)
```

Default `SESSION_BILLING_COST_MARKUP=1.0` (pass-through). This is independent
of `messages.metadata.usage.cost` (provider cost).

### Context-window carryover

Each conversation turn replays the full message history. LobeHub reports
actual provider usage (`inputCacheMissTokens`, `inputTextTokens`), so
long threads naturally consume more budget — no extra instrumentation needed.

## Implementation Steps

### Step 1 — Database: `usage_events` table

**File to create:** `packages/database/src/schemas/usageEvents.ts`

```typescript
export const usageEvents = pgTable(
  'usage_events',
  {
    id:             text('id').$defaultFn(() => idGenerator('budget')).primaryKey(),
    userId:         text('user_id').references(() => users.id, { onDelete: 'cascade' }).notNull(),
    occurredAt:     timestamp('occurred_at').defaultNow().notNull(),
    messageId:      text('message_id').references(() => messages.id, { onDelete: 'set null' }),
    model:          text('model'),
    provider:       text('provider'),
    weightedTokens: integer('weighted_tokens').notNull(),
    rawInput:       integer('raw_input'),
    rawOutput:      integer('raw_output'),
    costCents:      integer('cost_cents'),
  },
  (t) => [
    index('usage_events_user_time_idx').on(t.userId, t.occurredAt),
  ],
);
```

Notes:

- ID prefix `bgt_` via `idGenerator('budget')` — already registered in `idGenerator.ts`.
- `rawCached` column dropped; cache tokens are already in `messages.metadata.usage`.
- `costCents` = user-facing charge, not provider cost.

Then generate the migration: `bunx drizzle-kit generate`.

**Model class:** `packages/database/src/models/usageEvent.ts`

User-scoped constructor, three methods:

```typescript
class UsageEventModel {
  constructor(db: LobeChatDatabase, userId: string) {}

  insert(params: {
    messageId?: string;
    model: string;
    provider: string;
    weightedTokens: number;
    rawInput: number;
    rawOutput: number;
    costCents: number;
  }): Promise<void>

  // Rolling 5-hour window
  getSessionWindow(): Promise<{ used: number; resetsAt: Date | null }>

  // Fixed calendar week (resets Sunday 00:00 UTC)
  getWeeklyWindow(): Promise<{ used: number; resetsAt: Date }>
}
```

### Step 2 — Billing service

**File to create:** `src/server/services/sessionBilling/index.ts`

Gate the entire module behind `process.env.SESSION_BILLING_ENABLED`.

```typescript
// Returns 2 during peak (5–11 AM PT), 1 otherwise. DST-aware.
peakMultiplier(date: Date): number

recordUsage(params: {
  userId: string;          // no-op when undefined (bot/eval contexts)
  messageId: string;
  model: string;
  provider: string;
  modelUsage: ModelUsage;
}): Promise<void>
// weightedTokens = totalTokens * peakMultiplier(now)
// costCents      = Math.round(modelUsage.cost * SESSION_BILLING_COST_MARKUP * 100)

getBudget(userId: string): Promise<{
  session: { used: number; limit: number; resetsAt: Date | null; isPeak: boolean };
  weekly:  { used: number; limit: number; resetsAt: Date };
}>

assertBudget(userId: string): Promise<void>
// throws SessionLimitExceededError when used > limit (session OR weekly)
```

**Error shape:**

```typescript
class SessionLimitExceededError extends TRPCError {
  code = 'FORBIDDEN'
  data = {
    code: 'SESSION_LIMIT_EXCEEDED',
    resetsAt: string,   // ISO date
    used: number,
    limit: number,
  }
}
```

**Environment variables:**

| Variable                          | Default   | Purpose                       |
| --------------------------------- | --------- | ----------------------------- |
| `SESSION_BILLING_ENABLED`         | `false`   | Master switch                 |
| `SESSION_LIMIT_TOKENS`            | `200000`  | 5-hour session cap            |
| `SESSION_LIMIT_TOKENS_WEEKLY`     | `1000000` | Weekly cap                    |
| `SESSION_BILLING_PEAK_MULTIPLIER` | `2`       | Peak-hour token weight        |
| `SESSION_BILLING_COST_MARKUP`     | `1.0`     | User-facing charge multiplier |

## Key risks

| Risk                                                        | Mitigation                                                                             |
| ----------------------------------------------------------- | -------------------------------------------------------------------------------------- |
| One-turn lag: breach detected after the turn that caused it | Accepted for v1; pre-flight estimation deferred                                        |
| DST boundary in `peakMultiplier`                            | Unit-test at `2024-03-10` (spring forward) and `2024-11-03` (fall back) PT transitions |
| Sunday reset off-by-one (today *is* Sunday)                 | Explicit test cases for Sunday before and after 00:00 UTC                              |
| Sub-agents / group orchestration consume budget             | `accumulateLLM` fires per hop → `recordUsage` captures all hops                        |
| Self-hosted operators don't want billing                    | Gate on `SESSION_BILLING_ENABLED=true` (off by default); table is harmless when empty  |

| ----------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `peakMultiplier`  | Peak hour mid-window, off-peak mid-window, exactly 05:00 PT, exactly 11:00 PT, `2024-03-10 01:59 PT`, `2024-03-10 03:01 PT`, `2024-11-03` fall-back hour |
| `assertBudget`    | Under limit passes, over limit throws, `used === limit` passes (strict `>`)                                                                              |
| `getWeeklyWindow` | Mid-week, Saturday 23:59 UTC, Sunday 00:00 UTC, Sunday 00:01 UTC                                                                                         |
| `recordUsage`     | Peak event stores `totalTokens * 2`, off-peak stores `totalTokens * 1`, `userId` undefined → no-op                                                       |

then confirm send re-enables after `resetsAt`.
